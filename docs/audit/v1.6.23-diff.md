# v1.6.23 — what changed after `v1.6.22-audit`

One page for AstraSec.

- **Base:** the tag `v1.6.22-audit` (tag object `bbb7a6a`, commit `a2c0bae`).
- **Scope:** one feature, the buy-back button's tip floor.
- **Runtime code:** only `FeastHook` moves, 24,330 → 24,437 B (EIP-170 margin 139). Every other
  contract is byte-identical (`test/FeastBytecodePin.t.sol`).
- **Details:** `docs/audit/changelog-v1.6.23.md`, with the ruling at `plans/675/ruling.md`.

## What changed

1. **The constructor takes a table.**
   - The new last parameter is `TipFloor[] tipFloors`, one `(quote, floor)` row per listed quote.
   - The rows go into `mapping(address => uint256) internal _tipFloorOf`, declared after every
     audited variable. The audited slots (`_pools` 0 … `_referrerOf` 3) do not move; the table is
     slot 4.
   - The constructor emits `TipFloorListed(quote, floor)` per row.
   - It refuses a zero floor or one over 2^128 (`TipFloorOutOfBounds`), and a repeated quote
     (`TipFloorListedTwice`).
   - No function writes the table afterwards, and there is no getter.
2. **The Buyback lock callback returns a fourth word:** `_tipFloorOf[quote]`. Only
   `buyBackAndBurn` decodes that return data.
3. **The tip site in `buyBackAndBurn`** (was one line):

   ```solidity
   uint256 tip = coinOut * FeastConstants.TIP_BPS / FeastConstants.BPS;          // unchanged
   if (floor != 0) {
       uint256 largest = pending / (FeastConstants.BPS / FeastConstants.ALLOWANCE_CAP_BPS);
       uint256 floored = largest / (FeastConstants.BPS / FeastConstants.TIP_CEILING_BPS) >= floor
           ? coinOut * floor / largest
           : coinOut / (FeastConstants.BPS / FeastConstants.TIP_CEILING_BPS);
       if (floored > tip) tip = floored;
   }
   ```

   So `tip = coinOut × max(0.25%, min(floor ÷ largest, 10%))`. `largest` is 5% of the bucket before
   the press.
4. **New constants:** `FeastConstants.TIP_CEILING_BPS = 1_000` and
   `TIP_FLOOR_NATIVE = 0.0005 ether`. The second is read only by the deploy script.
5. **Deployment:** `FeastGenesis.tipFloors()` is an empty placeholder for the stock rows, and
   `DeployPackage1.tipFloors()` builds the table. Each row is worth 0.0005 BNB at deploy.

## Why

At 0.25% of a 5% print, a press paid 0.0125% of the bucket. With about \$0.13 of gas, no bucket
under about \$1,040 was worth pressing, so small coins' buckets sat.

The owner's floor makes a bucket of about \$26 worth a press. The floor is divided by the **largest**
press the bucket allows, not by the press being made:
- **The rule as first written** divided by this press. A presser could then split into presses of
  `10 × floor` and take 10% of all spend on any bucket. That is R6.
- **As ruled,** the rate is set by the bucket. There is still no flat component per press, and
  splitting earns nothing. `test_splittingAPressEarnsNothing` goes red under the written rule.

## Worth a look

- **The arithmetic.**
  - Both constants divide `BPS`, so both quotients are exact. `test_theTipsConstantsAreTheRuledOnes`
    pins this.
  - The first branch implies `largest ≥ 10 · floor ≥ 10`, so there is no division by zero.
  - `coinOut < 2^127` (an int128 delta) and `floor ≤ 2^128 − 1`, so the product is below 2^255.
  - Everything is checked arithmetic.
- **A global, per-quote table read by every pool.** It carries no value, and nothing writes it
  after deployment. So it is configuration, not per-pool state; see I7 below.
- **The callback's return shape.** The Buyback action is internal to the hook.

## Invariants untouched

- **The press's accounting.** `coinBurned + tip == coinOut`, and the event is unchanged. The tip is
  at most `⌊coinOut/10⌋`, so at least 90% is burned; it was 99.75% before, and still is for buckets
  over 8,000 floors.
- **The pacing.**
  - It is still 5% per press, 15% refilled per hour, and at most 20% in any hour.
  - The allowance and the bucket are still debited by the realised `quoteSpent` alone. The floor
    changes how `coinOut` is split, never what is spent.
- **The button's other bounds.** The TWAP admission, the swap's price limit, the gate check and the
  freeze guard are unchanged.
- **P10.** The internal fill pays no tip, and its code is unchanged.
- **P11.** The button's `Trade` is unchanged.
- **P20.** There is no new state-changing function. The table is constructor-only.
- **P27–P29.** Unchanged.
- **Every other P row.** No code on its path moved.
- **V1-CARRIED.**
  - I4 still holds: the buttons are bounded, and the tip is capped and paid out of the output, with
    the cap now at 10%.
  - I7 (per-pool isolation) holds: the table is read-only configuration keyed by quote. No pool can
    read or write another's accrual, caps, buckets or oracle through it.

## What was reworded, not weakened

"The tip is a fixed fraction … no flat component" is now "no flat component per press — the rate
is set by the bucket, not the press". This applies to `docs/interface.md` and `docs/site-census.md`,
and the census row names the new witnesses.
