**HIGH**

**H1 — Permissionless conversion still accepts attacker-selected economic valuations.**

The converter computes expected output entirely from the selected pools’ prices, checks each against its own history, and accepts output within 3% of that expectation. No independent quote/native valuation bounds protocol spending. [src/TorchConverter.sol:150](src/TorchConverter.sol:150), [src/TorchConverter.sol:184](src/TorchConverter.sol:184)

Construction: an attacker supplies genuine, mature Q/X and X/WBNB pools, with attacker-issued X and directional liquidity that accepts valuable Q while delivering negligible WBNB. Their prices can remain constant throughout the observation window. Adequate liquidity lets both hops consume their complete inputs with little impact.

Any caller can route a permitted platform-bucket amount through those pools. The attacker’s liquidity receives Q; the protocol receives negligible native value. Every new consumption check passes. [src/TorchHook.sol:860](src/TorchHook.sol:860), [src/TorchHook.sol:894](src/TorchHook.sol:894)

The accepted route set remains economically wider than intended.

**H2 — Wrapped-native platform entitlement still has no spending path.**

For WBNB input, an empty route is refused; every nonempty route must end in WBNB; and any occurrence of the input token is forbidden. No route satisfies all three predicates. [src/TorchConverter.sol:134](src/TorchConverter.sol:134), [src/TorchConverter.sol:139](src/TorchConverter.sol:139), [src/TorchConverter.sol:144](src/TorchConverter.sol:144)

`convertPlatformQuote` still calls the converter unconditionally. Ordinary fees from the required platform-coin/WBNB pool therefore accumulate a platform allocation that cannot become `platformNative`. The purchase button only spends already-settled native. Smaller requests, deeper liquidity and waiting cannot fix this contradictory admission set. [src/TorchHook.sol:894](src/TorchHook.sol:894), [src/TorchHook.sol:927](src/TorchHook.sol:927)

WBNB-denominated `claimAsBnb` also fails, although beneficiaries retain direct quote claims. [src/TorchHook.sol:743](src/TorchHook.sol:743)

**H3 — Positive dust can occupy all three hourly intervals. The conversion site is newly affected.**

Both purchase buttons accept any positive output. The restored conversion clock likewise consumes an hour whenever conversion produces any positive native amount. [src/TorchHook.sol:832](src/TorchHook.sol:832), [src/TorchHook.sol:889](src/TorchHook.sol:889), [src/TorchHook.sol:946](src/TorchHook.sol:946)

With mature pools and substantial buckets, an attacker front-runs a productive press using a fully consumed input that produces only a few raw output units. The tip may round to zero. The productive press then fails for an hour. Repeating at expiry suppresses meaningful spending indefinitely.

The conversion interval fixes sequential draining, but introduces another site for the acknowledged progress defect. Full consumption does not establish meaningful progress.

**H4 — Finalization can erase an entire funded reward entitlement.**

Finalization clears accrued funding and constructs an index using `floor(accrued × 10^27 / totalFees)`. Claims depend on that index. [src/TorchEpochRewards.sol:203](src/TorchEpochRewards.sol:203), [src/TorchEpochRewards.sol:217](src/TorchEpochRewards.sol:217), [src/TorchEpochRewards.sol:233](src/TorchEpochRewards.sol:233)

Construction: one payer records `10^30` raw quote-fee units during E; purchases fund E with 999 raw platform units. At closure:

`floor(999 × 10^27 / 10^30) = 0`

The sole payer receives zero, while all 999 funded units remain held. The empty-epoch rollover cannot apply because fees are positive. No denomination restriction makes those platform units necessarily insignificant. This construction uses ordinary open-epoch funding; it does not require access to `creditPotClosed`.

**M1 — The size-cap dust fallback can leave an entire remaining bucket unspendable. Fresh.**

All three buttons permit the entire remainder only when the calculated 20% ceiling is **zero**. [src/TorchHook.sol:813](src/TorchHook.sol:813), [src/TorchHook.sol:869](src/TorchHook.sol:869), [src/TorchHook.sol:929](src/TorchHook.sol:929)

Construction: leave five raw quote units in a self-burn bucket, with a mature, liquid pool. The ceiling is one. With low-decimal quote tokens, five raw units need not be economically negligible. This is owned entitlement, outside the stray-balance boundary.

**M2 — Delayed finalization lets callers select the beneficiary epoch of an empty pot.**

Eligibility therefore depends on maintenance-call timing. The existing test only exercises immediate next-epoch finalization. [test/TorchEpochRewards.t.sol:194](test/TorchEpochRewards.t.sol:194)
