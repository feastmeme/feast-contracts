**MEDIUM**

**M1 — The gate does not cover the hook’s own buyback swap.**

`buyBackAndBurn` checks funding, allowance and price history, but never `openAt`. Its venue swap skips the hook callbacks, including the only gate check. It subsequently pays a token tip to its caller. [Buyback entry](src/FeastHook.sol:844), [swap](src/FeastHook.sol:564), [tip](src/FeastHook.sol:885).

Concrete construction:

1. Genesis uses the existing fixture’s valid 1:1 seed configuration and sets `openAt = genesisTime + 25 hours`.
2. At `genesisTime + 24 hours`, the named opener buys with `10e18` wrapped-native units, without a referral. The opening block cap has expired.
3. This banks a fee of `99,009,900,990,099,009` units and a self-burn entitlement of `79,207,920,792,079,208`, and records the prevailing tick.
4. Leave the price unchanged for 300 seconds. The oracle now accepts its history, and spending allowance is `990,099,009,900,990` units.
5. A stranger calls `buyBackAndBurn(key, 1e18)`. The request is clamped to that positive allowance; the deep pool produces positive output, the hook completes the swap before `openAt`, and the stranger receives a positive tip.

This violates P5. It requires an earlier opener swap; I did **not** establish a buyback before the first opener swap, when the oracle has no observations. The gate tests exercise router swaps only, and the gate census omits this path. [Tests](test/FeastGate.t.sol:40), [census](docs/site-census.md:162).

**Fix and second-order check:** explicitly refuse hook-owned buybacks while gated. Preserve the opener’s ordinary swap path and post-opening buybacks. Enabling the skipped callbacks instead would introduce self-fees and opening-cap checks into v1’s buyback path.

**M2 — Genesis accepts allocation recipients that leave 35% of supply permanently in the factory.**

The three allocation recipients need only have code. Consequently, the genesis key can supply:

```solidity
teamVesting = address(factory);
emissions   = address(factory);
grants      = address(factory);
```

Keep the window, sink, gate and seed parameters valid. All recipient checks pass, as does the initial whole-supply custody check. Each subsequent allocation transfer is a self-transfer. Genesis succeeds with `350_000_000e18` FEAST still in the factory and `genesisDone == true`. No factory function can release those existing tokens. [Checks](src/FeastFactory.sol:228), [transfers and completion](src/FeastFactory.sol:262).

This is an authorized configuration error, not a permissionless attack. It nevertheless directly contradicts P9’s mandatory empty-factory outcome. The split witness uses distinct external holders and therefore misses it. [Witness](test/FeastGenesis.t.sol:148).

**Fix and second-order check:** reject the factory as any allocation recipient and enforce a zero final factory balance. This preserves legitimate allocations and introduces no recovery authority or new swap refusal.
